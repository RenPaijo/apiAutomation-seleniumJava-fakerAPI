# FakerAPI — API Automation

## Test API
`GET /api/v2/persons` on https://fakerapi.it/ — free public fake-data API, no auth required. The automated flow requests 10 male persons born between 1990-01-01 and 2000-12-31 using `_quantity=10`, `_gender=male`, `_birthday_start=1990-01-01`, and `_birthday_end=2000-12-31`. It checks that 10 persons are returned, every gender is `male`, and every birthday falls within the inclusive date range.

## Prerequisites
- JDK 17+, Maven 3.8+
- Internet access to https://fakerapi.it
- Allure CLI for viewing the report (`npm install -g allure-commandline` and ensure `allure` is on PATH); alternatively, use the `allure-maven` plugin

## Setup
```bash
# 1. Check Java and Maven
java -version
mvn -version

# 2. Resolve dependencies
mvn dependency:resolve

# 3. Compile tests
mvn test-compile
```

## Run
```bash
mvn clean test
```

## Structure

├── config/ApiConfig.java            # base URL and endpoint path
├── model/Person.java                # single person data model
├── model/PersonsResponse.java       # API response envelope data model
├── controller/PersonController.java # HTTP request and response mapping
└── view/PersonView.java             # readable response table
src/test/java/com/fakerapi/
└── PersonsApiTest.java              # scenario, evidence, and assertions
pom.xml
README.md
.gitignore
```

## MVC
- **Model** (`model/`): request/response data only. `Person` represents one person, `PersonsResponse` represents the API response envelope. No assertions or business validation live here.
- **Controller** (`controller/`): the only place that talks HTTP. `PersonController.getPersons(...)` receives the request parameters, sends the GET request with query parameters, deserializes the response into `PersonsResponse`, and returns the person data. No assertions or business validation live here.
- **View** (`view/`): presentation only. `PersonView.format(...)` renders the person list as a readable text table, printed to the console and attached to the Allure report as evidence. It performs no requests, no validation, and decides no pass/fail.
- **Config** (`config/`): `ApiConfig` keeps the base URI and endpoint path in one place instead of hard-coding them in the controller or test.
- **Test** (`PersonsApiTest`): owns the scenario. It calls the controller, uses the view for presentation evidence, then asserts total equals 10, every gender is `male`, and every birthday is within range. It never builds HTTP requests directly.

## Reports
- Surefire: `target/surefire-reports` (generated by `mvn test`)
- Allure:
  ```bash
  mvn clean test
  allure serve target/allure-results
  ```
  Results are written to `target/allure-results` (configured in `pom.xml`). If the report shows 0 test cases, serve `target/allure-results`, not a legacy root-level `allure-results/` folder. Without the Allure CLI, generate a static report:
  ```bash
  mvn allure:report
  ```
  Open `target/site/allure-maven-plugin/index.html` in a browser.
